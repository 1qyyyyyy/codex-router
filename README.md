# 应用出口路由器

当前发布版本：1.3.1。状态面板采用原生窗口、冷灰深色主题、蓝色主操作和分区状态摘要，支持显示器缩放与窗口调整。解压后双击 `CodexRouter.exe` 即可打开客户端，不需要批处理入口，也不会弹出命令窗口。

这是一个视窗版域名分流工具。采用本地代理的应用，其目标域名流量经过你指定的上游代理，其他域名由电脑直连。它不是虚拟网卡或透明代理，不能强制拦截忽略系统代理、忽略代理环境变量的软件。

## 客户端入口

发布目录只提供一个可执行程序入口：`CodexRouter.exe`。配置文件、使用说明与第三方许可保存在旁边。

1. **启动后台**：先检测上游，成功后启动独立后台进程，备份并启用当前用户系统代理和代理环境变量。重复启动不会创建第二份后台。
2. **停止后台或恢复代理设置**：释放监听端口，恢复启动前的系统代理、自动配置和用户代理环境变量。后台被意外结束时，再次打开客户端恢复遗留设置。
3. **运行诊断**：执行六步检查，显示每步结果与处理建议，支持展开详情及复制完整报告。
4. **上游配置**：直接修改主机地址与端口；保存后下次启动后台生效。

直接启动时始终使用程序旁的 `config.yaml`，缺失时创建默认配置，不覆盖已有配置。移动程序时请连同配置文件一起移动。

启动成功后，必须完全退出桌面应用以及它的后台进程，再从开始菜单重新打开。已经运行的应用、终端或编辑器不会自动获得新环境变量；从旧终端重新启动也可能继续继承旧值。结束代理后，同样需要重启应用。

不需要管理员权限；不会自动结束你的联网应用。关闭面板与停止后台是两个独立动作。

面板右上角的关闭按钮会隐藏到托盘。右键托盘可重新显示面板，或选择“退出面板（后台继续运行）”。退出面板不会停止代理或恢复系统设置；需要停止时选择“停止后台”。打开面板本身不会自动启动代理。

## 六步诊断

点击“运行诊断”会依次检查上游端口、协议、认证、目标连接、本地入口、系统代理。每步显示“通过”“失败”或“跳过”，失败附带对应建议；前置失败导致无法确认的后续步骤不会被假报通过。后台未运行时，仍会检查本地端口占用、遗留备份及可确认的代理残留；无法执行的转发检查标记为跳过。后台运行时，本地入口实际请求检测目标，系统代理步骤核对系统设置和用户代理环境变量。只有跳过时会明确提示未全部通过。

网页代理拒绝认证的状态码 `407` 与目标网站的 `401`、`403` 分开处理。目标网站的权限拒绝可以证明网络连接建立，不代表账号或应用功能可用；目标服务的服务器错误会报告失败。诊断不会覆盖后台已有健康状态。

## 配置真实出口

编辑同目录的配置文件：

```yaml
upstream:
  type: auto
  host: 127.0.0.1
  port: 1080
  name: 手机出口
  username: ""
  password: ""
```

上述地址和端口仍是示例，不代表手机实际出口。填写的是**电脑能连接到的手机共享代理监听地址和端口**，不是手机内部加密节点地址。手机必须提供网页代理或第五版套接字代理入口，并允许共享网络的电脑接入；仅开启数据线共享网络不代表已经共享代理。

知道协议时可填写 `http` 或 `socks5`，否则保留自动识别。密码可引用环境变量；后台继承启动命令的环境，不会记录密码。

本地入口默认是电脑回环地址的 `17890` 端口。上游检测失败、配置无效或监听端口占用时，启动会报错，不会为了显示成功而把系统代理指向不可用入口。

配置解析失败时会给出可确认的行号、已知字段和修改建议；未知字段只显示所在配置区域。错误提示不回显密码、未知键名或检测地址中的查询参数。文件不存在与访问权限不足仍有对应提示。

## 域名分流

默认包含以下根域名及其子域名：

```yaml
targets:
  - openai.com
  - "*.openai.com"
  - chatgpt.com
  - "*.chatgpt.com"
  - oaistatic.com
  - "*.oaistatic.com"
  - oaiusercontent.com
  - "*.oaiusercontent.com"
```

通配子域名不包含根域名，所以二者分别列出。自定义模型供应商或额外认证网站需要将其域名补入列表。此列表是路由配置，不是完整应用网络目的地的保证。

目标域名的上游连接失败时返回错误，不会静默回退直连；非目标域名仍然直连。不要同时使用其他工具自动切换系统代理，否则可能覆盖本工具的设置；运行诊断会报告被覆盖的设置。

本地入口最多同时处理 `256` 个普通请求或隧道，达到上限时返回暂时不可用并提示稍后重试；关闭隧道、请求结束或取消后归还额度。普通转发请求等待目标响应头最多 `120` 秒，正文及已建立的加密隧道不设整段时长上限。空闲连接池最多保留 `64` 条连接，每个目标最多 `16` 条，闲置 `90` 秒后释放。

## 如何判断实际生效

健康检测只证明一次检测请求的连接情况，不能证明账号可用、模型调用可用、所选公网出口正确或全部应用请求已经代理。

启动并重启应用后执行一次实际操作，再查看状态面板中的最近应用目标：这里只记录后台观察到的目标域名连接，展示时间、主机与端口、节点和成功或失败结果；周期健康检测和内部诊断流量不会计入。也可查看 `logs/codex-router.log` 的隧道建立或请求完成记录。没有真实应用目标记录时，检测通过不能证明应用已使用代理。

`logs/background.log` 只保留本次后台启动的错误输出，每次重新启动覆盖；运行日志统一写入配置指定的日志文件，不重复写入后台启动日志。运行日志每个文件最多 `10 MiB`，保留最近三份备份，备份以 `.1`、`.2`、`.3` 结尾。升级时会裁剪已有超大运行日志的旧内容，保留末尾记录。

`data/health.json` 保存最近检测状态。主动停止或调用者取消检测时保留最后一次有效结果，不写入一次“异常”；检测器自身的网络超时仍记为异常。日志不记录请求正文、查询参数、认证标头或代理密码。加密隧道无法读取应用请求正文。

面板分别显示后台运行情况、上游健康及检测时间、最近真实应用目标，三者不能相互替代。健康结果会检查新鲜度，过期结果不会冒充当前健康；后台未运行时，旧状态文件不会被当作当前运行证据。一键诊断是独立检查，不会让旧的后台健康时间自动更新。

面板新增“网络延迟”：后台启动后立即测量，之后每 5 秒通过当前上游向配置的健康检测地址发送一次请求，单次最多等待 5 秒。显示值是建立连接、加密握手及读取少量响应的总耗时，单位为毫秒；同时显示采样时间。检测超时、连接异常和结果过期会分别提示，失败耗时不会显示为有效延迟。监测在后台异步执行，不阻塞面板，不覆盖周期健康状态文件，也不计入真实应用目标记录；停止后台后停止监测。“复制状态”也包含网络延迟。

系统代理和环境变量只对采用它们的应用有效；使用自带网络栈、硬编码直连、其他代理配置或特殊网络协议的流量可能绕过本工具。当前版本不宣称全系统、全部功能强制接管。

## 停止和恢复

在客户端点击“停止后台”或“恢复代理设置”，不要直接删除 `state` 目录。该目录保存后台身份信息和原代理备份；恢复成功后会清理对应文件。恢复失败会保留备份并显示错误，不能当作成功结束。

如果原来没有用户代理环境变量，结束后会删除本次设置；原来有值时恢复原值。系统自动配置和自动检测标志也会恢复。退出不会删除你填写的上游配置。

在后台运行期间不要移动、删除发布目录或修改监听地址；需要改配置时先停止后台，再修改和重新启动。后台不是开机服务，注销或重启电脑后应先打开客户端恢复遗留设置，再重新启动后台。

面板“上游配置”可直接修改主机地址和端口。修改后“保存配置”才会启用；后台运行时先停止，再保存并重新启动后台使新的出口生效。保存与后台共用互斥锁，状态未清理时会阻止保存。端口或地址错误在配置区就地提示。修改后还应完全退出并重新打开联网应用。

“重新载入配置”会重新读取磁盘文件，存在未保存修改时先提示确认。健康结果过期会明确标记，健康检测不能证明应用已经使用代理。“复制全部”始终复制完整诊断报告；“查看详细记录”切换精简步骤与完整说明。状态自动刷新会保留输入内容、诊断文字选区和滚动位置。可用制表键切换操作，回车键执行当前按钮或保存已修改的配置。

## 高级命令

```powershell
.\CodexRouter.exe start --config .\config.yaml
.\CodexRouter.exe stop --config .\config.yaml
.\CodexRouter.exe status --config .\config.yaml
.\CodexRouter.exe tray --config .\config.yaml
.\CodexRouter.exe panel --config .\config.yaml
.\CodexRouter.exe diagnose --config .\config.yaml
.\CodexRouter.exe health --config .\config.yaml
.\CodexRouter.exe check --config .\config.yaml
```

程序仍保留显式命令参数、应用启动器和系统服务接口，以兼容后台管理与旧用法。日常使用直接双击程序即可，发布目录不再提供批处理入口。不要同时运行旧前台代理、系统服务和新后台代理；它们会占用相同端口。

`tray` 与 `panel` 均打开状态面板，`diagnose` 输出完整六步诊断；`health` 保留旧的一次上游健康检测接口，不能替代完整诊断。

## 构建及验证

```powershell
go test ./...
go vet ./...
powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1
```

应用图标已嵌入程序，文件图标、窗口和托盘无需外部图标文件。原图与多尺寸图标位于 `assets` 目录，编译后的图标资源随源码保存在 `cmd/rsrc_windows_amd64.syso`，普通构建不需要额外工具。

更换原图后，安装图像处理依赖并重新生成资源（首次生成需要联网获取固定版本的资源编译工具）：

```powershell
python -m pip install Pillow
python ./scripts/generate-icon.py --go 编译器完整路径
```

统一执行普通回归、静态检查、非视窗交叉构建和发布打包：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\verify.ps1
```

可通过 `-GoExecutable` 指定编译器完整路径。额外传入 `-RunLifecycle` 会使用本地模拟上游执行后台启停、真实转发和异常终止恢复测试；这项验证会短暂修改当前用户代理设置，结束时恢复原值。

构建使用无控制台的视窗程序子系统，保留已有发布配置，并清理旧的批处理入口与程序备份。发布包只包含一个可执行程序、配置、说明及许可，不包含测试文件、运行日志、代理设置备份或后台令牌。打包后自动核对文件清单、逐文件哈希、处理器架构、图形子系统及程序版本，并生成压缩包的 `.sha256` 校验文件。

仓库自动流程在视窗环境分别使用最低声明版本与当前稳定版编译器执行验证，并在非视窗环境执行并发检查。通过验证的稳定版发布包保留十四天。真实后台生命周期测试只使用模拟上游，不依赖手机代理或账号。

真实后台生命周期测试需要显式设置 `ROUTER_TEST_BINARY` 指向构建后的程序。该测试会短暂修改当前用户系统代理及环境变量，并在结束时恢复；普通测试默认跳过这一项。具体结果和未验证范围见验证记录。

# 应用出口路由器

当前发布版本：1.2.1。状态面板采用深色界面、中文字体和彩色操作按钮。解压发布包后双击“状态面板”即可打开。

这是一个视窗版域名分流工具。采用本地代理的应用，其目标域名流量经过你指定的上游代理，其他域名由电脑直连。它不是虚拟网卡或透明代理，不能强制拦截忽略系统代理、忽略代理环境变量的软件。

## 四个入口

发布目录提供四个批处理文件：

1. **状态面板**：打开桌面控制面板和托盘入口，显示后台、本地入口、上游健康时间及最近真实应用目标连接。可直接启动后台、停止后台、一键检测和打开设置。
2. **检测出口**：执行六步诊断，显示每步结果及可操作建议。尚未启动后台时，会检查本地端口占用和遗留代理备份；无法执行的转发检查标记为跳过，不能据此声称应用已经使用代理。
3. **启动代理**：保持原来的双击启动习惯；先检测上游，成功后启动独立后台进程，备份并启用当前用户系统代理和代理环境变量。成功后可以关闭命令行窗口，不会停止代理。重复启动不会创建第二份后台。
4. **结束代理**：关闭后台，释放监听端口，并恢复启动前的系统代理、自动配置和用户代理环境变量。后台被意外结束时，再运行此入口恢复遗留设置。

启动成功后，必须完全退出桌面应用以及它的后台进程，再从开始菜单重新打开。已经运行的应用、终端或编辑器不会自动获得新环境变量；从旧终端重新启动也可能继续继承旧值。结束代理后，同样需要重启应用。

不需要管理员权限；不会自动结束你的桌面应用。关闭启动窗口与关闭后台是两个独立动作。

面板右上角的关闭按钮会隐藏到托盘。右键托盘可重新显示面板，或选择“退出面板（后台继续运行）”。退出面板不会停止代理或恢复系统设置；需要停止时选择“停止后台”或双击“结束代理”。打开面板本身不会自动启动代理。

## 六步诊断

一键检测或检测出口会依次报告上游端口、协议、认证、目标连接、本地入口、系统代理。每步显示“通过”“失败”或“跳过”，失败附带对应建议；前置失败导致无法确认的后续步骤不会被假报通过。后台未运行时，仍会检查本地端口占用、遗留备份及可确认的代理残留；无法执行的转发检查标记为跳过。后台运行时，本地入口实际请求检测目标，系统代理步骤核对系统设置和用户代理环境变量。发现失败时，完整输出报告后返回非零退出码；只有跳过时会明确提示未全部通过。

网页代理拒绝认证的状态码 `407` 与目标网站的 `401`、`403` 分开处理。目标网站的权限拒绝可以证明网络连接建立，不代表账号或应用功能可用；目标服务的服务器错误会报告失败。诊断不会覆盖后台已有健康状态。

## 配置真实出口

编辑同目录的配置文件：

```yaml
upstream:
  type: auto
  host: 127.0.0.1
  port: 1080
  name: 手机出口
  username: ""
  password: ""
```

上述地址和端口仍是示例，不代表手机实际出口。填写的是**电脑能连接到的手机共享代理监听地址和端口**，不是手机内部加密节点地址。手机必须提供网页代理或第五版套接字代理入口，并允许共享网络的电脑接入；仅开启数据线共享网络不代表已经共享代理。

知道协议时可填写 `http` 或 `socks5`，否则保留自动识别。密码可引用环境变量；后台继承启动命令的环境，不会记录密码。

本地入口默认是电脑回环地址的 `17890` 端口。上游检测失败、配置无效或监听端口占用时，启动会报错，不会为了显示成功而把系统代理指向不可用入口。

## 域名分流

默认包含以下根域名及其子域名：

```yaml
targets:
  - openai.com
  - "*.openai.com"
  - chatgpt.com
  - "*.chatgpt.com"
  - oaistatic.com
  - "*.oaistatic.com"
  - oaiusercontent.com
  - "*.oaiusercontent.com"
```

通配子域名不包含根域名，所以二者分别列出。自定义模型供应商或额外认证网站需要将其域名补入列表。此列表是路由配置，不是完整应用网络目的地的保证。

目标域名的上游连接失败时返回错误，不会静默回退直连；非目标域名仍然直连。不要同时使用其他工具自动切换系统代理，否则可能覆盖本工具的设置；检测出口会报告被覆盖的设置。

## 如何判断实际生效

健康检测只证明一次检测请求的连接情况，不能证明账号可用、模型调用可用、所选公网出口正确或全部应用请求已经代理。

启动并重启应用后执行一次实际操作，再查看状态面板中的最近应用目标：这里只记录后台观察到的目标域名连接，展示时间、主机与端口、节点和成功或失败结果；周期健康检测和内部诊断流量不会计入。也可查看 `logs/codex-router.log` 的隧道建立或请求完成记录。没有真实应用目标记录时，检测通过不能证明应用已使用代理。

`logs/background.log` 记录后台启动错误，`data/health.json` 保存最近检测状态。日志不记录请求正文、查询参数、认证标头或代理密码。加密隧道无法读取应用请求正文。

面板分别显示后台运行情况、上游健康及检测时间、最近真实应用目标，三者不能相互替代。健康结果会检查新鲜度，过期结果不会冒充当前健康；后台未运行时，旧状态文件不会被当作当前运行证据。一键诊断是独立检查，不会让旧的后台健康时间自动更新。

系统代理和环境变量只对采用它们的应用有效；使用自带网络栈、硬编码直连、其他代理配置或特殊网络协议的流量可能绕过本工具。当前版本不宣称全系统、全部功能强制接管。

## 停止和恢复

优先使用结束代理，不要直接删除 `state` 目录。该目录保存后台身份信息和原代理备份；恢复成功后会清理对应文件。恢复失败会保留备份并返回错误，不能当作成功结束。

如果原来没有用户代理环境变量，结束后会删除本次设置；原来有值时恢复原值。系统自动配置和自动检测标志也会恢复。退出不会删除你填写的上游配置。

在后台运行期间不要移动、删除发布目录或修改监听地址；需要改配置时先结束代理，再修改和重新启动。后台不是开机服务，注销或重启电脑后应先运行结束代理恢复遗留设置，再重新启动代理。

面板“设置”会打开配置文件。应先点击“停止后台”，确认恢复成功，再打开设置修改并保存，最后重新启动后台；修改后还应完全退出并重新打开应用。

## 高级命令

```powershell
.\CodexRouter.exe start --config .\config.yaml
.\CodexRouter.exe stop --config .\config.yaml
.\CodexRouter.exe status --config .\config.yaml
.\CodexRouter.exe tray --config .\config.yaml
.\CodexRouter.exe panel --config .\config.yaml
.\CodexRouter.exe diagnose --config .\config.yaml
.\CodexRouter.exe health --config .\config.yaml
.\CodexRouter.exe check --config .\config.yaml
```

程序仍保留前台运行、应用启动器和系统服务接口，以兼容旧用法，但发布目录不再提供启动应用的批处理入口。不要同时运行旧前台代理、系统服务和新后台代理；它们会占用相同端口。

`tray` 与 `panel` 均打开状态面板，`diagnose` 输出完整六步诊断；`health` 保留旧的一次上游健康检测接口，不能替代完整诊断。

## 构建及验证

```powershell
go test ./...
go vet ./...
powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1
```

构建会保留已有发布配置，并删除旧的启动应用批处理。批处理采用无字节序标记的 UTF-8 和视窗标准换行。发布包不包含运行日志、代理设置备份和后台令牌。

真实后台生命周期测试需要显式设置 `ROUTER_TEST_BINARY` 指向构建后的程序。该测试会短暂修改当前用户系统代理及环境变量，并在结束时恢复；普通测试默认跳过这一项。具体结果和未验证范围见验证记录。
